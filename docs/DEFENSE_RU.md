# Подготовка к защите

## Linux и команды

Linux предоставляет серверную среду, права файлов, процессы и Bash; Jenkins и
контейнеры выполняют одинаковые автоматизированные команды на каждом запуске.

| Команда | Что делает |
|---|---|
| pwd | Печатает текущий каталог |
| ls -la | Показывает файлы, включая скрытые, владельцев и права |
| cd | Меняет текущий каталог оболочки |
| mkdir -p | Создаёт каталог и недостающие родительские каталоги |
| touch | Создаёт пустой файл или меняет его временные метки |
| cp | Копирует файл |
| mv | Перемещает или переименовывает файл |
| rm | Удаляет файл; штатной корзины в этой команде нет |
| cat | Выводит содержимое файла |
| head -n 3 | Показывает первые три строки |
| tail -n 5 | Показывает последние пять строк |
| find . -name application.log | Ищет файл по имени внутри текущего каталога |
| grep ERROR logs/application.log | Показывает строки с ERROR |
| grep -c ERROR logs/application.log | Считает строки с ERROR, в нашем примере 2 |
| chmod | Меняет права доступа |
| whoami / hostname / date | Пользователь, имя узла, дата |
| uname -a / df -h / free -h | Ядро, диски, оперативная память |
| ps / ps aux / top | Снимок процессов / расширенный снимок / обновляемый монитор |

Процесс — запущенная программа с памятью, состоянием и ресурсами. PID — числовой
идентификатор процесса в пространстве PID. В `ps aux` USER — владелец, PID — номер,
%CPU — процессор, %MEM — доля памяти. В контейнере видимость процессов ограничена.

Права: r=4 чтение, w=2 запись, x=1 выполнение. Три цифры относятся к owner,
group и others. `600` означает rw-------: личный файл доступен только владельцу.
`644` означает rw-r--r--: владелец пишет, остальные читают. `755` означает
rwxr-xr-x: владелец читает, пишет и выполняет; остальные читают и выполняют.
Для каталога x означает возможность прохода по пути, r — просмотр имён,
w вместе с x — создание и удаление записей каталога.

Скрипт вычисляет корень относительно своего расположения, поэтому проверка
информационного файла работает даже при запуске из другого каталога.

## Git и GitHub

Git хранит локальную историю изменений. Коммит — снимок подготовленных через
`git add` изменений с автором и сообщением. `git status` показывает состояние
рабочего дерева и индекса. GitHub размещает удалённый Git-репозиторий для обмена
кодом и получения исходников Jenkins.

Ветка — перемещаемая ссылка на коммит; позволяет работать над изменением отдельно.
В проекте development содержит добавление документации и объединяется в main
через merge commit. `git log --oneline --graph --all` показывает обе линии.

`git push` отправляет локальные коммиты в удалённый репозиторий.
`git pull` получает изменения и интегрирует их в текущую ветку (merge или rebase
согласно настройкам). `.gitignore` исключает логи, временные копии и `.env` из
обычного добавления: они не являются исходным кодом, могут содержать секреты.
Это не средство шифрования и не защита уже опубликованного секрета.

## Docker

Образ — неизменяемый шаблон файловой системы и конфигурации. Контейнер — экземпляр
образа с процессами и записываемым слоем; контейнер может быть запущен или остановлен.
Удаление контейнера не удаляет образ.

FROM задаёт базовый образ Python. WORKDIR задаёт каталог последующих RUN, COPY и CMD.
COPY переносит исходники. RUN выполняет шаг при сборке: проверяет компиляцию и
создаёт пользователя. EXPOSE документирует внутренний порт 8000; публикация
на хост выполняется через -p или ports в Compose. CMD задаёт стартовую команду.
USER переключает приложение на student. HEALTHCHECK проверяет HTTP /health.

Переменная окружения — пара имя=значение, доступная процессу. Docker передаёт
её через -e, Compose через environment. Один образ можно запускать с разными
данными без пересборки. Секреты нельзя зашивать в образ или Git: их могут прочесть
из файлов и истории слоёв. Для реальных секретов применяют специализированные
secret stores; обычные переменные также видимы тем, кто имеет доступ к Docker.

`docker logs` показывает stdout/stderr главного процесса. stop посылает сигнал
завершения, start запускает остановленный контейнер, rm удаляет его, exec запускает
дополнительную команду внутри работающего контейнера. Compose описывает сервисы,
порты и окружение в YAML, делая запуск воспроизводимым; up создаёт и запускает,
down останавливает и удаляет контейнеры и сеть проекта.

## Jenkins и общий workflow

Jenkins — сервер автоматизации. Он получает Jenkinsfile и исходники из GitHub,
фиксирует конкретный Git SHA, компилирует Python, запускает тесты, собирает образ
и запускает проверяемый контейнер. GitHub хранит код; Jenkins выполняет команды.
Образ обеспечивает одинаковую среду запуска после тестов. Тесты проверяют
значения по умолчанию, все env overrides, здоровье, экранирование HTML и 404.

При старте Pipeline агент выделяет workspace, Checkout получает код, Build
проверяет синтаксис, Test проверяет поведение, Docker Build создаёт образ с тегом
номера сборки, Docker Run запускает контейнер и проверяет реальный HTTP ответ.
Тег latest изменяемый; номер сборки помогает связать результат с запуском Jenkins.
Точный исходный коммит напечатан в Checkout и виден в данных Jenkins build.

Если Docker Build завершается ошибкой, Docker Run пропускается и весь запуск
получает FAILURE. Строку Finished: SUCCESS можно показать только у реального
успешного запуска. Ручной Build Now запускает Pipeline без webhook; webhook
может автоматизировать запуск по push, но в задании он не обязателен.

## Практические вопросы

```bash
git switch -c verification
git switch main
find . -name application.log
grep ERROR logs/application.log
git log --oneline --graph --all
docker logs tajibayev-assylbek-container
docker exec tajibayev-assylbek-container printenv STUDENT_GROUP
STUDENT_GROUP=DEMO docker compose up -d
curl http://localhost:8086/api/student
STUDENT_GROUP=IT2-2310 docker compose up -d
```

Последние строки используют синтаксис Bash. В PowerShell переменную задают
`$env:STUDENT_GROUP='DEMO'`, а затем запускают `docker compose up -d`.
